# Архитектура и логика проекта

## Общая идея

Два файла: `train.py` (обучение) и `app.py` (инференс). Без отдельных слоёв `models/`, `utils/` — проект небольшой, лишние абстракции только мешают.

## Данные

HAM10000 — 10015 дерматоскопических изображений, 7 классов поражений кожи. Оригинальные картинки (450×600) слишком тяжёлые для локального обучения на CPU/GPU без выделенной видеокарты, поэтому использована уменьшенная версия (112×150), пересобранная через pickle.

### Конвертация данных

Исходный pickle-файл был сохранён старой версией pandas (2022 год) и несовместим с текущей. Решение: одноразовое виртуальное окружение со старыми `numpy`/`pandas` только для распаковки, затем сохранение в независимые от версии форматы — `images.npy` (numpy-массив) и `metadata.csv`. Дальше проект работает с этими файлами, версия pandas больше не важна.

## Обучение (`train.py`)

**Модель**: ResNet18, предобученная на ImageNet. Обучение с нуля на 10к изображений привело бы к переобучению — transfer learning даёт готовые низкоуровневые фичи (грани, текстуры, цветовые паттерны).

**Что заморожено / разморожено**:
- Все слои заморожены, кроме `layer4` (последний свёрточный блок) и `fc` (финальный классификатор)
- Ранние слои ResNet учат универсальные фичи (грани, углы) — они одинаково полезны для любых изображений, дообучать их незачем
- `layer4` учит более специфичные, высокоуровневые паттерны — их дообучение под конкретную задачу (дерматоскопия) даёт основной прирост качества

**Дисбаланс классов**: `nv` (доброкачественная родинка) — 67% датасета, `df` (дерматофиброма) — всего 1%. Без коррекции модель просто научится всегда предсказывать `nv` и получит обманчиво высокую accuracy. Решение — `class_weight="balanced"` в функции потерь, штрафующей ошибки на редких классах сильнее.

**Аугментация**: случайные повороты и отражения. Дерматоскопические снимки не имеют "правильной" ориентации — родинка выглядит одинаково узнаваемо под любым углом, поэтому такая аугментация не искажает смысл данных, а просто увеличивает эффективный размер обучающей выборки.

**Устройство**: `mps` (Metal Performance Shaders) — использует GPU-ядра Apple Silicon вместо CPU, обучение в разы быстрее без необходимости внешнего GPU или облака.

## Оценка качества

Общая accuracy — обманчивая метрика при таком дисбалансе классов (см. выше). Вместо неё — `classification_report` с precision/recall по каждому классу отдельно и матрица ошибок, чтобы видеть, какие классы путаются друг с другом.

Ключевая метрика для этой задачи — recall на `mel` (меланома): пропущенный случай (ложноотрицательный) намного опаснее ложной тревоги (ложноположительный). Модель специально настроена жертвовать precision ради recall на этом классе.

## Инференс (`app.py`)

Модель загружается один раз через `st.cache_resource` — не переобучается и не перезагружается с диска при каждом взаимодействии с интерфейсом. Загруженное изображение проходит те же трансформации (resize, нормализация), что и при валидации во время обучения — без аугментации, она нужна только для увеличения обучающей выборки.

## Что сознательно не сделано

- Разморозка всех слоёв ResNet — риск переобучения на датасете в 10к изображений, прирост неочевиден
- Ансамбль нескольких моделей — усложнение архитектуры без чёткой необходимости на этом масштабе задачи
- Сегментация поражения (выделение границ) — отдельная, более сложная задача компьютерного зрения, не входит в scope классификатора
- Календарь/трекинг истории поражений во времени — вне рамок MVP, это уже другой продукт
